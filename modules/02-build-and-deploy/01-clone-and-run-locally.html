1. Clone the team repo and run it locally

Author

Mr. John Jennings

Who: every team member, on their own laptop. Goal: the Gallery app running on your laptop, reading the sample data from a MySQL database in Docker.

1.1 Check your tools

Open a terminal (PowerShell, Terminal or Git Bash) and run each check:

Tool Check Expect
JDK 17 java -version 17.x. IntelliJ users can skip this: IntelliJ downloads JDK 17 for you
Docker docker --version A version number, and Docker Desktop running
Git git --version A version number

You do not need Maven: the repo includes the Maven wrapper (mvnw), which downloads the right version itself.

1.2 Accept the invitation

Your lecturer has added you to your team’s repo on their GitHub account. Accept the invitation from the email GitHub sent you, or from https://github.com/notifications. Until you accept, the repo URL gives a 404.

1.3 Clone the repo

Use the URL your lecturer gives you in class. It looks like https://github.com/<lecturer>/<team-repo>.git.

  • IntelliJ
  • Command line
  1. File → New → Project from Version Control.
  2. Paste the URL and choose a folder.
  3. When asked, sign in with GitHub in the browser.
  4. Click Clone, then Trust Project.
  5. Bottom right, click the branch name (main) and choose origin/develop → Checkout.
  6. File → Project Structure → Project: set SDK to a Java 17 JDK. If there is none, open the list → Download JDK → version 17, Eclipse Temurin.
git clone https://github.com/<lecturer>/<team-repo>.git
cd <team-repo>
git switch develop

The repo is private, so Git asks you to sign in. On Windows, a browser window opens: sign in to GitHub there. Do not type your GitHub password at a terminal prompt; GitHub rejects passwords for Git.

You work from develop, never main. main only changes at a release (step 6).

1.4 Start the database and phpMyAdmin

The repo’s docker-compose.yml defines three services:

Service What it is Address on your laptop
db MySQL 8.4, holding the idm3project2024 database localhost:3306
phpmyadmin A web page for browsing and editing the database http://localhost:8081
app The Gallery app, built in Docker http://localhost:8080

For day-to-day work you start only db and phpmyadmin, and run the app itself from IntelliJ or Maven (1.5).

  • IntelliJ
  • Command line

Open docker-compose.yml and click the green ▶ in the gutter beside the db: service, then beside phpmyadmin:. Both appear in the Services tool window (Alt+8, or ⌘8 on a Mac). Wait until db shows healthy.

Do not start app: here: you run the app from IntelliJ in the next step, and both use port 8080.

From the repo folder:

docker compose up -d db phpmyadmin
docker compose ps

Wait until db shows healthy; run docker compose ps again if it says starting.

The first run downloads the MySQL and phpMyAdmin images, which takes a minute or two. The first time db starts, it also loads the sample data from idm3project2024.sql: users, projects and showcases.

Check the data is there. Open http://localhost:8081. If phpMyAdmin shows a login form, sign in as the app’s database user:

Setting Value
Username / password gallery / gallerypass
Database idm3project2024
Root user, if you ever need it root / rootpass

On the left, open idm3project2024. It has four tables: project, showcase, showcaseproject and user. Click user to see the sample accounts you will log in with.

From the command line, the same check is:

docker compose exec db mysql -ugallery -pgallerypass idm3project2024 -e "SHOW TABLES;"

The warning about using a password on the command line is expected.

Note

These passwords are in docker-compose.yml, in Git, so they are for your laptop only. The test and prod servers use their own passwords, stored as secrets in your team repo. phpMyAdmin is never deployed to test or prod.

1.5 Run the app

  • IntelliJ
  • Command line

Open src/main/java/idm3/project/gallery/application/GalleryApplication.java and click the green ▶ beside the class → Run ‘GalleryApplication’.

dev is the default profile. Set it explicitly anyway, so you know where the setting lives: Run → Edit Configurations → GalleryApplication → Active profiles: dev → OK.

./mvnw spring-boot:run

In PowerShell, use .\mvnw.cmd spring-boot:run. On macOS or Linux, if you get Permission denied, run chmod +x mvnw once.

Open http://localhost:8080. It redirects to the gallery home page at /MainGallery/HomePage, which lists the sample projects and showcases. Check:

Role Username Password
Student TRYAN pass123
Student MSith 123pass
Administrator tsmith pass123
Administrator EBourke Bourke123
Employer PCbus PC123
NoteA 404 after signing in means it worked

A successful login redirects to /dashboard, which your team has not built yet, so you see a 404 page. A wrong password keeps you on the login page with an error.

These accounts come from the sample data. Their passwords are stored as plain text, which is acceptable only on your laptop: replacing them with real, hashed passwords is part of your team’s work in weeks 2 to 4. You can also create your own student account at http://localhost:8080/MainGallery/Register.

Stop the app with Ctrl+C, or the red ■ in IntelliJ.

1.6 Run the build CI runs

Keep db running: the test starts the whole app, including its database connection.

./mvnw verify

(.\mvnw.cmd verify in PowerShell. In IntelliJ, open the Maven tool window → Lifecycle → double-click verify.)

It compiles the app, runs its tests and packages it. If it ends with BUILD SUCCESS, your laptop builds the app as the pipeline will. CI starts its own empty MySQL for this, so never write a test that depends on the sample data.

1.7 Optional: run the whole stack in Docker

Stop the app you started in 1.5 first, because this uses port 8080 too. Then:

docker compose up --build

This builds the app’s Docker image from the Dockerfile and runs it next to MySQL. It is close to what the test and prod servers do. Open http://localhost:8080, then stop it with Ctrl+C.

If the build fails at ./mvnw with exit code 127, mvnw was checked out with Windows line endings. Your repo needs a .gitattributes file containing /mvnw text eol=lf. Once it has one, run rm mvnw and then git checkout -- mvnw, and build again.

1.8 Reset your database

To throw away your local data and reload the sample data, for example after a teammate changes idm3project2024.sql:

docker compose down -v
docker compose up -d db phpmyadmin

-v deletes the database volume, so everything you added locally is gone.

Troubleshooting

Symptom Fix
Repository not found when cloning You have not accepted the invitation, or you are signed in to Git as a different GitHub account
Cannot connect to the Docker daemon Start Docker Desktop and wait until it says it is running
Port 3306 or 8081 already in use Another MySQL or phpMyAdmin is running, often a container from another project. Run docker ps, then docker stop <name>
Port 8080 already in use An old run of the app is still going. Stop it in IntelliJ, or close the terminal running it
Communications link failure, or HHH000342: Could not obtain connection followed by a NullPointerException db is not running. Start it (1.4), wait for healthy, then start the app again
Access denied for user 'gallery' The database login in application.properties no longer matches docker-compose.yml. Both should be gallery / gallerypass
The home page is empty, or the test logins fail The sample data did not load, usually because the database volume already existed. Reset it (1.8)
Invalid source release: 17 Your terminal or IntelliJ is using another JDK. Check java -version, or the SDK in Project Structure
maven-wrapper.properties: No such file or directory The hidden .mvn folder is missing, usually because the project was copied rather than cloned. Clone it again
Unable to find a @SpringBootConfiguration in a test The test is missing @SpringBootTest(classes = GalleryApplication.class)
TipCheckpoint

db is healthy, the app shows the sample projects at localhost:8080 with local dev in its footer, a test login works, and mvnw verify is green. Tell your team, and move on when everyone has reached this point.
