7. Check the prod deployment

Author

Mr. John Jennings

Who: the whole team. Goal: confirm the release is running on prod, and know how to roll back if it is not.

7.1 Follow the deployment

Open Actions → deploy-prod. The newest run is named after your tag, e.g. v0.1.0. Check that:

If the run stays Queued with Waiting for a runner, start the lab in the account that holds gallery-prod, and start the instance if it is stopped.

7.2 Check it in the browser

Open http://<prod-ip>/ and run the same checklist as on test (step 5.2):

Prod and test should now look the same, because they run the same code. Prod uses the prod Spring profile; test uses test.

7.3 Confirm which release is running

On the prod server:

docker ps --format '{{.Image}}  {{.Status}}'

It prints gallery:v0.1.0 Up … minutes. Record the release, its date and the prod URL on your team’s board: this is your deployment record.

7.4 Roll back a bad release

If a release breaks prod, put the previous one back first and fix the problem afterwards.

From GitHub: open Actions → deploy-prod, click the run for the previous tag (e.g. v0.1.0) and choose Re-run all jobs. It builds and deploys that tag again.

On the server, faster: the previous image is still there, so start it directly:

docker images gallery
docker rm -f gallery
docker run -d --name gallery --restart unless-stopped \
  -p 80:8080 -e SPRING_PROFILES_ACTIVE=prod gallery:v0.1.0

Then fix the problem on a feature branch, check it on test, and release a new version, e.g. v0.2.1 (steps 4 to 6).

WarningBefore the assessed release

The skeleton’s student1 and other in-memory accounts are a week 1 convenience. Before v1.0.0 in week 11, login must use real accounts stored in the database, and the seed accounts must be gone from prod.

What you have built

From now on, every change follows this path: a feature branch, a reviewed pull request into develop, a check on test, then a release pull request into main and a tag to reach prod.

TipCheckpoint

http://<prod-ip>/ serves release v0.1.0, the team knows both server addresses, and everyone can explain how a change reaches prod.
